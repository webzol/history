# 阅史记 · 微信隐私指引配置

2026-11-16。代码已接入隐私提示；微信后台的声明仍需由 TD 配置。

## 先完善后台声明

1. 登录当前 AppID 对应的微信公众平台。
2. 现网版本入口：**账号设置 → 服务内容声明 → 用户隐私保护指引 → 去完善**。
3. 按实际功能声明 **「使用你的相册（仅写入）权限」**，对应 `wx.saveImageToPhotosAlbum`。用途可填写：**「为了将用户主动生成的历史分享海报保存到设备相册，申请相册的仅写入权限，仅用于保存用户选定的海报。」**
4. 运营主体、联系方式等字段按真实情况填写，提交平台审核。不要勾选「未采集隐私」。
5. 提审新代码时，核对 **管理 → 版本管理 → 提交代码审核 → 信息填写页面** 中的隐私指引。现网声明与提审版本声明的修改入口分别生效，需分别确认。

当前代码不读取微信头像、昵称、手机号、位置或相册照片；随机史客身份由本地产生。收藏、浏览足迹、阅读设置保存在设备，可从「我的 → 清除缓存」清除。后台声明应以实际调用为准，后续增加隐私接口需同步更新。

仅加代码弹窗无法解决平台通知：未声明的隐私类型会导致对应接口被禁用。官方文档说明，补充声明的隐私类型在 5 分钟后生效；仍需核对审核状态。

## 弹窗行为

- 每次启动后查询微信 `getPrivacySetting`；有待同意的指引才提示。微信已记录同意则不弹，不使用本地缓存假装已同意。
- 弹窗链接通过 `openPrivacyContract` 打开后台的正式指引；「我的」也提供常驻入口。
- 同意通过 `button open-type="agreePrivacyAuthorization"` 的原生事件同步给微信。
- 「暂不同意」关闭提示，允许继续阅读；同一会话切页不重复打扰。
- 保存海报前调用 `requirePrivacyAuthorize`，若用户尚未同意则再次提示；拒绝取消保存，同意后继续原保存流程。隐私同意和相册系统权限是两个独立步骤。
- 全部 13 页挂载同一原生组件，支持分享链接直接进入详情页；全应用只注册一次授权监听，切页或卸载时结算旧请求。
- 微信低版本缺少相关能力时保留原相册授权流程。自定义弹窗基础库要求为 2.32.3 及以上。

## TD 发版前验证

1. 微信开发者工具选择 3.x 基础库，清除授权数据后启动，确认首次弹窗及正式指引链接。
2. 选择「暂不同意」，浏览四个 tab，确认不影响阅读且不重复弹窗。
3. 人物/史事/朝代/资料详情 → 共此卷 → 保存卡片，确认重新征询；拒绝不保存，同意后才进入相册权限流程。
4. 重启已同意的小程序，确认不重复提示；从分享链接直接进详情页再次检查。
5. 小屏、特大字号及返回正式隐私指引后的状态需真机核对。网页预览只模拟微信授权，不代替平台验证。

自动验证：`node tools/privacy_selftest.js`、`node tools/selftest.js`、`python tools/validate_miniprogram.py`。

## 真机不弹框排查

现象：网页预览、`privacy_selftest` 全过，但真机（开发者工具模拟器 / 体验版）看不到弹框。

**先看真机日志**：`utils/privacy.js` 已打印 `[privacy] needAuthorization=... contract=...`。`wx.getPrivacySetting` 的 `needAuthorization` 只有四种取值（官方文档原文）：

| 后台声明状态 | 用户是否同意过 | needAuthorization |
|---|---|---|
| 未声明隐私收集类型 | —— | **false** |
| 已声明 | 已同意 | false |
| 已声明 | 未同意 | true |
| 已声明，之后又新增类型 | 之前同意过 | true |

**结论**：日志出现 `needAuthorization=false` 且你**没有同意过**时，就是**后台未声明**——真机不弹框的根因，代码无法绕过。按本文第一部分去公众平台声明后，补充类型约 **5 分钟生效**。若保存海报时报 `errno 112` / `api scope is not declared`，同样是这个原因。

按可能性排序的检查清单：

1. **后台未声明 / 未通过审核**（最常见）。自查：公众平台 → 账号设置 → 服务内容声明 → 用户隐私保护指引，确认「使用你的相册（仅写入）」已声明且审核通过。提审时勾了「未采集隐私」会导致接口被回收。
2. **声明入口搞错**：现网版（入口1）与提审/开发版（入口2）是两套，分别生效。体验版看的是入口2。
3. **该微信号已同意过**：`needAuthorization=false`、监听不触发。删掉小程序（微信下拉 → 最近使用的小程序 → 删除）或工具里「清除授权数据」后再试。
4. **真机基础库 < 2.32.3**：相关接口与 `open-type` 都不存在。用「低版本兼容」逻辑判断（已改为判断 `wx.getPrivacySetting` 是否为函数，不用 `wx.canIUse`——它的数据文件可能漏报新版 open-type）。
5. **没有任何隐私接口被真正调用**：`onNeedPrivacyAuthorization` 只在调用隐私接口/组件、且无同意记录时才触发；首次弹窗依赖启动时 `getPrivacySetting` 主动查询。
6. **刚点过「拒绝」**：微信侧可能短时间内抑制再次触发，删小程序重进复测。
7. **只在开发者工具里测**：模拟器与真机在授权行为上存在差异，以**真机调试 / 体验版**为准。

官方依据：[填写说明](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)、[隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)、[隐私接口对应信息类型](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/miniprogram-intro.html)。
